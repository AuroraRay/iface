护理方案打卡、使用日历与使用计划

文档类型：功能 PRD（中等深度） · 所属产品：个人护肤品存量管理系统 · 状态：待评审 · 版本 v1.0 · 2026-11-05
前置依赖：现有库存模型（产品含剩余量百分比、功效标签、分类）、概览页预设方案卡片（美白/保湿/抗老/油痘/日间防护）

1 背景与目标

系统目前已能记录"库存有什么、还剩多少、何时过期"，并通过预设方案展示"美白该用哪套"。但存在三个断层：

  • 方案只展示、不可执行——看完方案仍要逐个产品去库存页手动记使用，一次护肤要操作 4~5 次；
  • 使用记录散落——使用记录只存在于单产品抽屉里，用户无法回答"我这周坚持护肤了吗、哪天漏了"；
  • 有意图、无承诺——"这个月想美白"这类目标只能靠记忆，没有承载和追踪的地方。

本次迭代围绕"从管理库存到管理使用"升级：自定义方案让用户定义自己的 routine，一键打卡让执行变成一次点击，日历让坚持可见，计划让目标可追踪。预期可观察结果：完成一次整套护肤的记录操作 ≤ 2 次点击；任意历史日期可查当日用了哪些方案与产品；进行中的月度计划能看到打卡进度与目标产品消耗。

3 产品模型

3.1 对象定义

对象字段规则
护理方案
Routine		 id · 名称 · 图标 · 步骤列表 · 是否预设（系统） / 自定义（用户） · 创建时间 预设方案（美白/保湿/抗老/油痘/日间防护）不可删除、不可改步骤，可复制为自定义方案后修改；自定义方案可增删改
方案步骤
RoutineStep		 步骤类型（洁面/爽肤水/精华/面霜/防晒等） · 步骤名 · 关联产品（从库存选择，0~1 个） · 默认用量（百分比，5% 步进，范围 1~100） · 备注 与现有预设方案的"功效/分类匹配"并存：自定义步骤直接绑定具体产品，不做模糊匹配；默认用量即打卡时的预填扣减量
打卡记录
CheckIn		 id · 方案 id · 日期（YYYY-MM-DD） · 明细列表［产品 id · 实扣用量］ · 创建时间 一次打卡 = 一条打卡记录 + N 条产品使用记录（复用现有使用记录体系）；打卡记录不可编辑，仅可撤销（见共享规则 R3）
使用计划
Plan		 id · 月份（YYYY-MM） · 目标条目列表 · 周排程列表 · 状态（进行中 / 已归档） · 创建时间 同一时间允许存在多个进行中计划，但每个计划绑定唯一月份；跨月不自动续期，需手动创建新月计划
目标条目
Goal		 类型（功效方向 / 指定产品 / 指定方案） · 目标值 · 备注 功效方向 = 功效标签（如"美白"），进度按关联产品消耗量统计；指定产品 / 方案 = 从库存与方案列表中选择
周排程
Schedule		 方案 id · 生效星期（周一~周日，多选） 一个计划可含多条排程；同一方案在同计划内仅一条排程；排程用于打卡提醒口径与进度统计，不自动执行

3.2 关键状态流转

打卡动作：点击方案卡"打卡" → 打开确认单（步骤产品逐行预填默认用量，默认全选） → 用户可取消勾选 / 调整用量 → 确认 → 逐产品扣减数量并生成使用记录 + 生成打卡记录 → toast 反馈（含撤销入口）
数量联动：产品剩余量扣至 0 → 自动标记"已用完"（沿用现有状态机，不新增状态）

4 功能需求

FR-A 自定义护理方案 P0

目的：让用户把"我实际怎么护肤"固化成可打卡的方案，而不是只能用系统预设。

入口与布局：概览页"护理方案"卡片右上角新增"管理方案"按钮，打开全屏弹层（Dialog）。弹层内分两区：左侧方案列表（预设 + 自定义，按创建时间倒序，预设置顶带"系统"标识），右侧选中方案的步骤详情。

ID能力触发处理规则结果与状态
FR-A1新建自定义方案 弹层内"新建方案"按钮 表单字段：名称（必填，≤20字）、图标（emoji 选择器，默认 🧴）、步骤（可增删排序，每步选步骤类型 + 可选绑定库存产品 + 默认用量）。步骤类型与绑定产品分类不一致时仅提示不阻断 保存后进入方案列表，概览页方案区同步出现该方案卡；toast"方案已创建"
FR-A2复制预设为自定义 预设方案卡上的"复制"按钮 深拷贝该预设全部步骤与默认用量，名称自动为"预设名+副本"，可立即编辑 同 FR-A1
FR-A3编辑 / 删除自定义方案 自定义方案卡"编辑 / 删除" 编辑复用新建表单并预填；删除需确认弹窗，文案明示"不会删除产品与历史打卡记录"。预设方案无删除入口 删除后方案卡消失；历史打卡记录保留方案名快照（防悬空引用）
FR-A4步骤绑定产品 步骤编辑器内"选择产品" 选择器按分类分组列出全部未用完产品；已用完产品置灰不可选但保留显示；每步最多绑定 1 个产品，不绑定则该步骤打卡时仅作提示不出现在确认单 保存后步骤行显示产品名与剩余量

异常与边界：方案内所有产品的数量均为 0 时，方案卡打卡按钮置灰，悬停提示"方案内产品已用完"；绑定的产品被删除后，步骤降级为"未绑定"并保留步骤类型，不阻断方案其余步骤打卡。

FR-B 一键打卡 P0

目的：把"记一次护肤"从逐产品 4~5 次操作压缩为 2 次点击（打开确认单 → 确认）。

入口：概览页每个方案卡右上角"打卡"按钮；P0 仅支持打卡当日。

点下方按钮体验：勾选/改量 → 确认 → toast 撤销

ID能力处理规则结果与状态
FR-B1确认单展示 逐行列出方案内已绑定产品的步骤：产品名、分类、默认用量（预填）；同产品多步骤合并为一行、用量累加。已用完 / 已过期产品行置灰且默认不勾选 弹层底部实时汇总"本次将扣减 N 件产品 · 合计 M%"
FR-B2勾选与调量 每行可取消勾选（本次未用该产品）；用量按 5% 步进调整，范围 1~100 且 ≤ 当前剩余量，超出时自动截断到剩余量并高亮提示 调整仅对本次打卡生效；不回写方案默认用量（P1 再评估"记住本次用量"）
FR-B3确认扣减 确认后按勾选行逐产品：生成一条使用记录（含本次用量与日期）→ 扣减剩余量 → 数量为 0 自动标记"已用完"；同时生成一条打卡记录关联方案与全部明细 toast"已打卡 · 美白提亮方案"+ 撤销入口；方案卡与日历即时刷新
FR-B4撤销 撤销仅限当日打卡；执行反向操作：删除该打卡记录与其全部使用记录、恢复产品数量与状态。撤销需二次确认 toast"已撤销打卡"；日历当日标记消失

异常与边界：确认单内全部行未勾选时"确认"按钮置灰；打卡与手动记使用并存——两者产生的使用记录格式一致，可互相统计；同一方案同一天可多次打卡（早晚各一次），每次独立生成记录。

目的：让"坚持护肤"可见，回答"哪天用了、用了什么、漏了哪天"。

两处承载：

ID能力位置与规则结果与状态
FR-C1迷你日历 概览页"保质期 / 存量"Tab 组新增第三 Tab"使用日历"：仅展示近 14 天，每天一格，有打卡的日子显示方案色圆点（多方案最多显示 3 点 + 数字），点击展开当日明细 当日明细 = 打卡方案名 + 每方案扣减产品数概览；无打卡日点击提示"当日无记录"

FR-D 使用计划 P0

目的：把"这个月想美白 / 想多用某产品"变成可追踪的承诺，并用周排程约定节奏。

入口与布局：概览页在"护理方案"上方新增"使用计划"区块：进行中的计划以卡片横排展示；"新建计划"按钮打开弹层表单。计划卡由三段组成：月份与状态 → 目标条目（含进度）→ 周排程。

ID能力处理规则结果与状态
FR-D1新建计划 字段：月份（默认当前月）、目标条目（≥1 条，类型三选一：功效方向=选功效标签 / 指定产品=选库存产品 / 指定方案=选方案）、周排程（可选，选方案 + 勾选星期，可多条） 保存后概览页出现计划卡；toast"计划已创建"
FR-D2目标进度 功效方向进度 = 当月内功效匹配产品的使用记录总量 ÷ 该组产品在计划创建时剩余量合计（上限 100%）；指定产品进度 = 当月该产品使用总量 ÷ 其计划创建时剩余量；指定方案进度 = 当月该方案打卡次数 进度条每日随打卡刷新；无排程无目标产品的计划显示 0%
FR-D3周排程展示与联动 计划卡列出每条排程："方案名 · 周一/三/五"；当日命中排程时：对应方案卡显示"今日计划"徽标，打卡确认单顶部提示"今日排程方案"；未命中不阻断打卡 排程仅作标识与统计口径，不自动扣减、不弹提醒
FR-D4排程命中率 计划卡显示排程进度：当月排程应打卡天数中实际打卡的占比（如"排程命中 8 / 12 天"），与目标进度并列展示 命中率仅统计排程方案的打卡记录，手动记使用不计入
FR-D5编辑 / 归档计划 进行中计划可编辑目标与排程、可归档；归档需确认，归档后只读并保留进度快照；每月月末不自动归档，跨月后计划卡显示"已过期月度"角标提示归档 归档计划从概览页主区移入"历史计划"折叠区

5 共享规则

规则定义
R1 用量口径 所有用量均为产品剩余量百分比（0~100，5% 步进）；打卡、手动记使用、撤销共用同一口径与同一使用记录格式，任何统计（月度趋势 / 目标进度 / 日历）不区分记录来源
R2 数量与状态联动 扣减后剩余量 = max(0, 当前剩余量 − 实扣用量)；扣至 0 自动标记"已用完"；撤销时按记录明细等额恢复，恢复后沿用现有状态机重算（不会把"已用完"误改为"过期"）
R3 打卡可逆性 打卡记录不可编辑，只能当日撤销；撤销需二次确认并完整回滚（记录 + 数量）。跨日不可逆，保证历史日历数据稳定
R4 方案删除隔离 删除自定义方案不删除其历史打卡记录与使用记录；日历与统计展示方案名快照；预设方案不可删除
R5 数据持久化 新增对象（自定义方案 / 打卡记录 / 计划）与现有库存、使用记录同等持久化于本地，刷新与重启不丢失；预设方案随版本升级更新，用户自定义方案不受版本升级影响
R6 时区与日期 打卡日期、日历展示、计划月份一律使用本地日期（YYYY-MM-DD），不做 UTC 换算
